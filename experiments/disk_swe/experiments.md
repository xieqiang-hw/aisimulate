# SWE-chat 实验记录

SWE-chat Claude Code 主会话，上下文上限 128K，每组 174,438 条请求。

联合 SLA：TTFT ≤ 1 秒，且单条请求平均 TPOT ≤ 30 ms。表中 TPOT 为报告的请求平均值；G1/G2/G3 复用率均为首次准入的对应复用 token 总数／输入 token 总数，总复用率为三层之和。SSD 累计读包含重复恢复，不能直接等同首次准入复用量。GB/TB 使用十进制。

配置：H200 SXM、1P1D，P/D 各 Attention TP8／DP1，MoE TP8／EP1；P、D 使用独立本地 G2 池，D 侧 DRAM 约 256 GB；P 侧本地 G3 约 56 TB。默认 SSD 读写各 8 GB/s／TP 分片，H2D 为 25 GB/s／TP 分片。每个 KV 块含 64 token。

本轮采用 v2 紧凑逐轮观测，不减少迭代：prediction/ 下 iteration_metrics.jsonl.gz 保存完整 P/D BS、token 数与时间；scheduler_states.jsonl.gz 只保存队列和 KV 状态的变化；scheduler_trace_metadata.json 保存字段定义与静态配置；scheduling_events.jsonl.gz 保存准入、抢占和重新准入。用 scripts/scheduler_trace.py 可流式还原具名字段。时间采用仿真时钟，字段口径见 docs/replay/engine/workers.md。

本轮共 40 组，最多 4 组并行，每组进程树内存预算 5 GB。实际耗时包含并行运行时的资源竞争，不直接和旧串行实验比较。
