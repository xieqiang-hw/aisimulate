全量摘要

前缀重合只统计同会话存在上一条保留请求的调用；首条调用不进入分母。128K 筛选可能使两条保留请求之间跨过被过滤的调用。

汇报时，建议区分这三个概念

模型调用 ≠ Agent 会话

一段编程任务可以经历多轮“调用模型 → 执行工具 → 携带结果再次调用”。每一轮都是一条推理请求，历史内容可能大量重复。

共同前缀 ≠ 缓存命中

本页比较实际 hash_ids 的连续相同前缀。是否命中 HBM、DRAM 或 SSD，还取决于缓存容量、淘汰和请求到达时机，不能从数据集本身直接得出。

会话交错 ≠ 真实推理并发

当前 timestamp 来自首次响应日志事件，是时间代理。没有可靠的每次调用开始和结束时间，就不能画出真实同时推理请求数；本页直接展示可确认的调用数量、活跃会话数和交错时刻。

样本重合 ≠ 全局公共 prompt

当前重建只包含日志可见消息，省略了系统 prompt 和完整工具 schema。不同会话样本重合较低，也不能据此断言生产环境没有可共享系统前缀。

来源、筛选与复核

同会话分组来自 source_requests.jsonl。当前基准 requests.jsonl 本身未提供 session_id／delay，会话联系用于本页分析，不意味着仿真已施加会话完成依赖。原始输入由源模型日志重建后使用 GLM-5.2 tokenizer 编码，不是源模型实际 token 数。

16-token 共同前缀由链式哈希逐块比较，尾部私有块不跨请求匹配；64-token 对齐值向下取整，用于说明引擎块粒度，不代表缓存驻留。会话片段为有目的选择，统计总体另列；矩阵右上角的未来调用不参与可复用候选。
