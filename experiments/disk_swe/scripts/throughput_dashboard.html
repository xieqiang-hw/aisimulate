怎么读这些图

积压回落，不代表响应及时

若到达与完成长期相近，但积压在高峰上升后又回落，说明系统能消化总量，却会让一部分请求等更久。高峰中完成超过到达，可能是在处理此前积压。

5 分钟曲线不是瞬时峰值

请求和 token 速率是分桶平均；队列数是桶末采样。桶内发生再消退的等待可能在图上不明显，因此同时保留逐请求事件计算的精确峰值。

归属时刻要区分

到达需求按请求时间戳计入；完成吞吐按请求结束时刻计入。窗口汇总中的“完成归属输出”将请求全部输出归入完成桶；D 生成速率曲线则使用实际逐轮记录。

还不能给出“算力吃满多少”

本页所选配置均已采集逐轮记录，可以查看上方分时执行统计。忙碌比例表示模型执行时间占比，不是芯片算力利用率；最大可持续吞吐还需结合后续加压实验判断。

本页使用已有 8×、16× 与 32× 独立请求开放式回放结果。每档叠加使用自己的 trace；不是带会话完成依赖的新数据。输入和输出 token 速率不能直接与 GPU 峰值 FLOPS 相除。
数据与配置来源

模型 GLM-5.2-FP8，H200 SXM，1P1D，各 TP8/EP8；HBM 自动 KV 容量，P 侧 DRAM + 本地 SSD，D 仅 HBM；SSD 写带宽固定 8 GB/s/TP，H2D/D2H 各 25 GB/s/TP，P/D 单轮预算 16,384 token，序列上限分别 32/256。

8×、16× 与 32× 指会话时间叠加倍率；三档 speedup 均为 1，没有额外时间压缩。
