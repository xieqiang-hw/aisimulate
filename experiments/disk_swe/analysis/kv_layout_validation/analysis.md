# KV 字节数口径修正与小样本验证

验证日期：2026-11-16。

GLM-5.2-FP8 的原生 DSA 布局为每 TP 分片 60,216 字节/token，64-token 块为 3,853,824 字节；TP8 整实例逻辑块为 30,830,592 字节。旧通用 MLA 估算按 BF16 得到 89,856 字节/token，且遗漏 DSA 索引布局。现在支持的架构复用原生模型存储公式，未知架构保留通用估算；显式 bytes_per_token 和 FPM 声明资源继续优先。

保留原容量块数：P DRAM 4,152 / 8,303 / 12,455 块分别为 128.0086 / 255.9864 / 383.9950 GB，D DRAM 8,303 块。盘框 5,436,678 块约 167.616 TB。以上均为十进制容量。

详细统计和原始结果路径见 summary.json。盘框 YAML 使用整框读/写分别 80 GB/s，固定 I/O 时延 0.1 ms；自然样本主要验证功能与字节数，不能作为容量压力或带宽收益结论。

## 回归测试

本次新增 7 个回归用例，覆盖 GLM 默认 FP8/显式 FP8/BF16、原本地路径及盘框编译后的字节数、显式字节数覆盖、原生模型错误不降级、FPM 声明资源绕过模型构建。与现有直接相关测试合计 142 passed，4 deselected（已有的 invalid-slots 参数化测试组）。

扩大测试中存在既有问题：G3 校验报错文案预期过时；memory 惰性模块与 monkeypatch 还原交互导致后续导出缺失；Collector 未安装。使用临时目录中的修改前 HEAD capacity.py 复测，仍能重现这些失败；没有把扩大测试表述为全部通过。日志位于 ~/project/tmp/kv-layout-*-tests.log。

本次只改 Python 容量解析及调用参数，没有修改 Rust 调度器、LRU 或传输竞争规则。当前环境为 editable 安装，新启动的 CLI 已使用修正源码，无需重新编译 Rust。旧全量结果保留，不能混同为修正后结果；正式全量实验尚未启动。
