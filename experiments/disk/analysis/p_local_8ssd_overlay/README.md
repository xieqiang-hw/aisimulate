# 2× 时间叠加下的 DRAM 复用

比较 GLM-5.2-FP8／H200、P 侧 DRAM 384 GB 的旧 2× 时间压缩与新 2× 时间叠加。通过新 trace 的 `parent_output_row` 对齐同一原始请求，共 665,415 对。时间窗口按**新 2× 的请求到达时间（UTC）**归桶，复用 token 取首次准入记录。窗口的百分点以该窗口的输入 token 数为分母。

## 多复用集中在哪些时机

叠加后的第 1～8 周，DRAM 净复用增幅依次为 **0.890、0.820、0.368、0.621、1.394、1.862、2.562、3.927 个百分点**。最大的增幅出现在第 8 周。按净增 token 数排名的前五天如下，叠加时间轴第 1 天是 2026-05-17。

| 叠加日 | 叠加 UTC 日期 | 净增 DRAM 复用 token | 占该日输入的增幅 |
|---:|---|---:|---:|
| 51 | 07-06 | 88,109,504 | 5.048 个百分点 |
| 50 | 07-05 | 50,714,752 | 5.575 个百分点 |
| 48 | 07-03 | 45,818,624 | 4.505 个百分点 |
| 35 | 06-20 | 42,670,144 | 3.180 个百分点 |
| 53 | 07-08 | 40,946,816 | 3.758 个百分点 |

## 增量来自哪些请求

新 2× 中，22,376 条请求的 DRAM 直接复用增加，共增加约 9.95 亿 token。另有 4,531 条减少，共减少约 1.38 亿 token，净增 **8.56 亿 token（1.878 个百分点）**。22,376 条增加的请求中，**22,373 条同时减少了 HBM 复用**。

全场 HBM 复用净减 **10.31 亿 token**，SSD 恢复净增 **1.74 亿 token**。两层新增的复用基本补上了 HBM 减少的部分。逐请求结果支持复用来源向下层转移，但尚未逐块追踪 HBM 淘汰原因。
