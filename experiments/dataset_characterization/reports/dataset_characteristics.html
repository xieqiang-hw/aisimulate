01 / 先明确比较口径

FreeInference 是多模型生产 agentic trace，输入为 o200k 角色 token 总和，输出为 provider completion tokens；映射到 GLM-5.2 不代表重新分词。SWE-chat 是 Claude Code 主会话重建，使用 GLM tokenizer；原始 system prompts 与 tool schemas 缺失，压缩或歧义处终止提取。SWE 时间是首个响应事件代理，不能视为真实请求到达或端到端延迟。这里的 SWE 指 SWE-chat，不等同于 SWE-bench 题目集。

基础数据包刻画原始回放负载；overlay 改变会话时间安排与密度，不能把其突发视为自然流量。token 比例只能提示负载形态，不能直接换算为 P/D 耗时或最优配比。

这批数据呈现什么特征？

FreeInference 的输入中位数为 68,182 token，SWE 为 39,659；输出中位数分别为 197 和 103。最长 1% 输出请求分别贡献 15.9%、16.9% 的输出 token，均需关注输出长尾。

每 5 分钟请求数的 CV 分别为 1.37、1.58。这些差异描述当前保留样本，受观察区间、提取过滤与分词口径影响。

05 / 缓存与角色组成的可观测边界

FreeInference 输入角色 token 组成：system 9.2%；user 5.8%；assistant 29.4%；tool 42.0%；tool_definitions 13.6%。

FreeInference provider cached / prompt token 总量比为 95.88%，覆盖 631,294 条保留请求。该比值使用 provider 自身口径，不与 o200k 输入长度相除。

SWE 数据包未提供可比较的 provider cache-read 与角色 token 计数，缺失不记作零。本报告不推断模拟器实际缓存命中率；真实命中还取决于路由、缓存容量、逐出与时间安排。完整 block hash 扫描未启用，FreeInference 的 25 GB requests 文件不为本报告重复解码。
